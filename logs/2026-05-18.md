## [23:55] Pinboard + Weave UI shipped (Plan 2)

UI layer for the new meal planner is on `feat/meal-planner-pinboard-weave-ui` (stacked on Plan 1's foundation branch).

### What landed

- **State coordination:** `usePlannerState` hook owns pins, filters, weave output, and a 10-deep undo stack. Auto-reweave fires with 400ms debounce when filters change after a plan is already woven.
- **Pinboard surface:**
  - `ConstraintChipBar` — six first-class chips (diet, weeknight/weekend time, squad, pantry-aware, anti-repeat, batch)
  - `InspirationChips` — multi-select rows for cuisines / moods / seasons (additive ranking, not restrictive)
  - `PinboardFeed` — picker-driven grid with per-card constraint-match badges (pantry %, diet ✓, time-fit, batch)
  - `PinTray` — sticky bottom thumbstrip with quality meter + "Weave the week →" CTA gated at ≥3 pins
- **Weave surface:**
  - `WeaveSummary` — pantry %, active cooking time, variety, leftover count, reweave, undo, "start cooking" link
  - `WeaveGrid` — day × meal-type cells; three archetypes (pinned solid, suggestion dotted, leftover translucent green)
  - `WeaveCell` — keyboard-accessible tap target with hover-revealed remove + pin-this-suggestion controls
  - `ConstraintPicker` — slide-over that opens **instantly** on cell tap, with explicit "✨ Suggest one for me" secondary CTA + 6s timeout (resolves the original "+" hang bug)
- **Three-state macro display:** `MacroSummary` shows energy/protein/carbs/fat. Unknown = em-dash, partial = `~` prefix with note, known = bold value. Goal-mode fills bars against per-day targets multiplied by duration. Lazy estimator polls `/api/recipes/[id]/estimate-macros` in 6-worker batches for any null macros and re-renders cells with the new values labeled "est."
- **API enhancements:**
  - `/api/recipes/picker` extended with `pantry_aware`, `pantry_missing_max`, `inspiration_tags`, optional `meal_type`, configurable `limit`. Pantry/inspiration ranking helper extracted to shared `src/lib/recipe-match.ts` and reused by `/weave` route.
  - `/api/plans/[id]/weave` now returns `recipes[]` metadata alongside `entries` + `summary` so the grid can render suggestion cells with real images, focal points, and macros — no N+1 fetches.
- **Cleanup:** retired the old `plan-grid.tsx`, `plan-page-client.tsx`, `recipe-picker-slideover.tsx` (replaced by Pinboard / Weave components). `saved-recipe-fit.tsx` kept because it's still referenced from `page.tsx`.

### What's not in this PR
- `/plans/[id]/cook` route (execution view, shopping list) — separate spec.
- Density ribbon polish (prompt saved earlier for a future session).
- Moodboard entries — will land once moodboard.config.ts merges into master.
- Drag-and-drop reordering between Weave cells — current model is click-to-swap.
