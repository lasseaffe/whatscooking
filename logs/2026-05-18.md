# 2026-05-18 — Meal Planner Foundation (Plan 1)

## [21:30] Pinboard + Weave foundation shipped

Backend foundation for the new meal planner is on `feat/meal-planner-pinboard-weave`.

### What landed

- **Spec + plan** committed under `docs/superpowers/specs/` and `docs/superpowers/plans/`. Plan 2 (UI layer) is queued.
- **4 additive migrations**:
  - `20260518f_meal_plan_pinboard.sql` — extends `meal_plans` with `pinboard_filters`, `last_woven_at`; expands status enum to include `woven`, `cooking`, `archived`.
  - `20260518g_meal_plan_pins.sql` — new `meal_plan_pins` table with owner-scoped RLS.
  - `20260518h_meal_entries_weave.sql` — adds `source` (`pinned`/`suggestion`/`manual`), `parent_clientid`, `locked`. Leftover-ness lives on the existing `is_leftover` boolean (orthogonal to source).
  - `20260518i_recipes_macros_batch.sql` — adds `sat_fat_g`, macro estimator metadata, `batch_friendly`.
- **Pure Weave solver** at `src/lib/weave-solver/` with 7 modules + 34 passing unit tests (Vitest). Deterministic at `seed=0`; reweave variation via explicit seed.
- **5 new API routes**:
  - `GET/POST /api/plans/[id]/pins` and `DELETE/PATCH /api/plans/[id]/pins/[recipeId]`
  - `POST /api/plans/[id]/weave` — runs the solver with pantry/inspiration matching folded in
  - `PATCH /api/plans/[id]` — extended existing handler with `pinboard_filters` + new status values, auth check preserved
  - `GET /api/recipes/picker` — constraint-aware picker (replaces autofill-on-click)
  - `POST /api/recipes/[id]/estimate-macros` — display-time LLM macro estimator with version-tagged caching
- **Recipe image fix**: `<RecipeImage>` now consumes `focal_x`/`focal_y` percentages with warm-tone gradient fallback (no more broken icons). Threaded through Discover, plan grid, recipe hero, scramble, recipe-card.
- **Eager macro estimator** wired into three user-facing recipe ingest paths: `/api/recipes/generate`, `/api/recipes/[id]` (Spoonacular cache), `/api/menu-scanner/import`.
